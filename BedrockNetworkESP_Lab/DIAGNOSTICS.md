# Diagnostics

The lab writes bounded JSONL events to `Documents/ClientLoader/BedrockNetworkESP_Lab.log` (512 KiB with three rotated backups) and keeps a separate rotating `ClientLoader.log` for ClientLoader's bridge. Lab reports are written under `Documents/ClientLoader/exports/BedrockNetworkESP_Lab/` and every successful write is checked against the byte count. System logging is the fallback if the Documents write fails.

At constructor/startup, window attach, background, termination, and each 300 render frames, it emits `StartupReport.json`, `ESPDiagnostic.json`, `GameDataDiagnostic.json`, `NetworkDiagnostic.json`, `SymbolResearch.json`, and `BuildManifest.json`. Each includes session/build identifiers. `StartupReport` probes bundle identity, architecture/OS, loaded module basenames, JavaScriptCore/ClientMenu runtime classes/selectors, installed script filenames/hashes, and filtered script-evaluation evidence from the existing ClientLoader log. Callback outcomes remain marked unknown where the current loader has no evidence.

The ESP report includes frame count, candidate snapshot count, unavailable/stale state, viewport/scale, per-category rejection counts, and boxes actually drawn. Fixture/test/server-ground-truth records are rejected by the live renderer. The tracker also exposes bounded event/update/removal/rejection/incomplete/stale counters and session generation.

Events identify their source (`TEST_FIXTURE`, passive capture, protocol decoder, in-process provider, or server ground truth). Source enum values describe provenance; they do not assert that a producer exists. This build has only fixture observations. The `BNEDataSource` vtable defines initialization, start, state, capabilities, last-error access, and clean shutdown, but no production adapter is implemented.

No network decoder or game-memory hook is implemented. `NetworkDiagnostic.json` reports `not-implemented`, unknown transport/payload readability, and zero decoded entity packets; it never asserts that traffic was encrypted or decrypted. `SymbolResearch.json` labels names as candidates only. No credentials, session keys, packet payloads, memory dumps, or entity samples are included. If the dylib never loads, it cannot write these files; use the instrumented ClientLoader's `ClientLoader.log` as the independent loader/JS fallback.
