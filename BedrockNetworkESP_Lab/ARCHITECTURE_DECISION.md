# Architecture Decision

**Decision:** use a separate arm64 native dylib loaded in the Minecraft process by adding a distinct `LC_LOAD_DYLIB` entry to a staged copy of the app executable. Render only from validated snapshots and a verified camera source. Keep observations behind the source-independent data-source/tracker contract. Do not use 3105 for native code or introduce an external proxy/IPC path without decoded live data.

## Required decisions

| Area | Decision and evidence |
|---|---|
| Runtime | **In-process, separate `BedrockNetworkESP_Lab.dylib`.** This matches the requested runtime. The lab package tool stages it beside ClientLoader. A synthetic package contains both dylibs and two load commands; actual two-dylib launch on an iPhone is not yet verified. |
| Loader | **Direct staged IPA load command.** The lab contains its own bounded arm64 Mach-O load-command helper and tests staging two distinct dylibs. It does not import or modify ClientLoader source. The repo README reports the original loader running on-device, but does not prove that a second dylib loads successfully. Signing and a device launch are required to verify. |
| Packaging / 3105 | **Do not use 3105 for the dylib.** The workspace 3105 archive contains a `Patches/Minecraft` tree with `Application/com.mojang.minecraftpe/Documents/ClientLoader/...` data, a settings file with no fields, and a schema-4 project plist. The 812-byte `Minecraft-2.3105` file is a schema-9, password-protected `3105PATCH` wrapper with a 403-byte encrypted payload; its contents are unavailable for inspection. Neither artifact demonstrates a native load command or dylib path. The sample `.plist.txt` calls itself a supposition. |
| 3105 answers | **1:** workspace patch tree targets app Documents paths, but applying it on device is not verified; **2:** no native load evidence; **3:** installed-device/app build support unknown; **4:** no inspectable dylib path in patch tree; encrypted payload details unknown; **5:** experimental packaging never writes to original files; **6:** separate dylibs can be staged side by side by the tested package helper, but runtime compatibility remains unknown; **7:** remove the lab dylib/load command by reinstalling the original app or a separately retained unmodified IPA, and delete this lab. Do not edit the original ClientLoader package. |
| Data source | **Network decoder is optional and currently blocked by missing evidence.** No authorized capture, negotiated protocol version, decoded entity update, or ground-truth comparison was supplied. The tracker consumes source-neutral observations; fixture tests are not live proof. No decryption, packet layout, hook, or offset is claimed. |
| Renderer / camera | **In-process non-interactive overlay design**, consuming copied validated snapshots and a separately published camera snapshot. Camera source starts unavailable; drawing is withheld until both entity position and camera data pass validation/freshness checks. Provisional bounds are explicitly approximate. No game camera adapter has been verified. |
| External app | **Not required for this architecture.** No companion app or IPC is created. An optional capture utility would be a separate future experiment only after it can recover useful data and a bounded, tested channel is justified. |
| Network proxy | **Not selected.** No traffic was observed, and a proxy neither injects the dylib nor guarantees readable entity state. A proxy/decoder is not worth connecting to the renderer until it produces validated observations. |
| Compatibility | **Verified payload only:** Minecraft iOS `1.26.33` / `1.26.33.01`, arm64, minimum iOS 15.0. Installed iPhone game/iOS version and second-dylib runtime compatibility are **unknown**. iOS compilation is blocked on this Linux host because `xcrun`/iPhoneOS SDK are absent. |
| Rollback | The lab packager writes a new output path and refuses to overwrite existing output. Original app, `ClientLoader.dylib`, and 3105 files are input-only. Keep the unmodified IPA; remove the experiment by uninstalling the staged build and reinstalling that IPA, or remove the experimental load command/dylib from a fresh copy. Deleting `BedrockNetworkESP_Lab/` removes its sources and build artifacts. |

## Verification boundary

**Verified locally:** source/package structure; synthetic tracker/projection tests; package creation with two load commands in a synthetic arm64 Mach-O; preservation of the input app executable; original-source hash checks. **Not verified:** iOS dylib compilation/signature, installation via 3105, actual two-dylib load, network entity recovery, actual camera, or in-game rendering. These are distinct gates, not implied by the package test.

The separate in-process dylib route is the only route with a concrete, locally testable load-command/package mechanism in the inspected project. Its second-library runtime remains a device test gate.
