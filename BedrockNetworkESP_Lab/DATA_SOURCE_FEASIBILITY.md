# Data Source Feasibility

## Decision

**No-go for claiming a live entity feed at this stage.** There is no authorized-session capture, negotiated protocol version, decoded entity packet, or ground-truth comparison in the workspace. Encryption on an actual Bedrock session remains **Unknown** because no live payload was observed. The supplied password-protected `MENU SR FFTH.3105` was not authenticated by the limited KDF/AES-GCM layouts tested; its script contents remain unavailable. The selected implementation is the source-independent tracker with explicitly synthetic fixtures; production-source selection is blocked pending evidence.

## Evidence and next decision

**Verified:** existing `CLEntityProvider` has no producer in the inspected source and starts unavailable. `CLCameraProvider` has no default camera matrix and starts unavailable. The supplied diagnostic reports no captured entities and no available candidate loader bridge methods. Static analysis describes Minecraft-owned Script API names but did not establish a callable loader API, private entity accessor, or camera matrix accessor.

**Unknown:** whether an authorized capture in a controlled session exposes decodable entity lifecycle and movement data; whether encryption applies in that particular session; whether a specific protocol library supports the negotiated protocol; and whether the supplied encrypted 3105 menu is executable, data-only, or a different package type. The provided `assetindexer...` companion is a UnityFS bundle version `2022.3.47f1`, with 16 `MonoBehaviour`, five `MonoScript`, one `AssetBundle`, no `TextAsset`, and UMA-related assembly/class names. This supports a Unity asset-bundle interpretation for that companion, not Minecraft Bedrock compatibility or a live-data interface.

The most useful next experiment is a controlled, non-sensitive capture plus matching server-side ground-truth log, with game version, protocol version, and entity spawn/move/despawn sequence recorded. Do not collect or export authentication tokens/session keys. If payload content is unavailable or encrypted, stop packet decoding and evaluate a supported Bedrock Script API test pack/server feed as ground truth; that would not prove client-only ESP viability. No undocumented hook, guessed packet layout, or offset is implemented here.
